# 要件定義（EARS）

## 1. 背景
本MVPは、PC作業画面のスクリーンショット画像から日報を自動生成する。
生成結果は以下3セクションで出力する。
- 作業内容
- 進捗状況
- 課題・問題点

## 2. ユーザーストーリー
- ユーザーとして、画像をアップロードして短時間で日報のたたき台を得たい。
- ユーザーとして、生成結果を手動で編集し、最終文面をコピーしたい。
- 管理者として、APIキーなどの秘匿情報を安全に管理したい。

## 3. 機能要件（EARS）
- 普遍的: システムは、日報を日本語Markdownテキストで返すこと。
- イベント駆動: 画像アップロード要求を受信したとき、システムはAzure OpenAIに画像付きプロンプトを送信すること。
- イベント駆動: 生成処理が成功したとき、システムは「作業内容」「進捗状況」「課題・問題点」の3見出しを含む本文を返すこと。
- 望ましくない動作: 画像形式がJPEG/PNG以外の場合、システムは400エラーと理由を返すこと。
- 望ましくない動作: 画像サイズが上限を超える場合、システムは413エラーを返すこと。
- 望ましくない動作: Azure OpenAI呼び出しに失敗した場合、システムは502エラーを返すこと。
- 状態駆動: 処理中の間、フロントエンドはローディング表示を行うこと。
- オプション: 生成結果が表示されている場合、システムはコピー操作を可能にすること。

## 4. 非機能要件
- セキュリティ: APIキーは環境変数管理とし、ソースコードにハードコードしない。
- 性能: 5MB以下の画像入力に対し、通常ケースで30秒以内に応答すること。
- 可観測性: サーバーはエラー内容を機密情報を除いてログ出力すること。
- 保守性: バックエンドロジックはAPI層とAzure OpenAI呼び出し層を分離すること。

## 5. 受け入れ基準
- 画像アップロードで日報3セクションが生成される。
- 不正な画像形式で適切なエラーが表示される。
- Azure OpenAIの設定不足時に起動時エラーが発生し、原因が明示される。
- 生成結果をUIからコピーできる。
- `.env` で endpoint/key/deployment を切り替え可能である。
