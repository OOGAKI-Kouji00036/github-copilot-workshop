# 日報アプリ MVP 要件定義（EARS）

## 1. 目的
本書は、`docs/daily-report-app-meeting.md` を一次情報源として、日報アプリMVPの要件をEARS（Easy Approach to Requirements Syntax）形式で定義し、実装スコープを固定することを目的とする。

## 2. 一次情報源
- `docs/daily-report-app-meeting.md`

## 3. スコープ定義

### 3.1 MVP対象（In Scope）
1. 画像アップロード
2. 日報生成
3. 編集 / コピー / Markdown出力
4. ローディング表示 / エラー表示
5. 一時データ削除

### 3.2 MVP非対象（Out of Scope）
1. モバイル最適化
2. OCR専用フロー
3. 永続DB（RDB / NoSQL など）

## 4. 機能要件（EARS）

| ID | 種別 | 要件（EARS） |
|---|---|---|
| REQ-F-001 | イベント駆動 | ユーザーが画像ファイルをドラッグ&ドロップ、貼り付け、またはファイル選択したとき、システムは画像をアップロード受付状態にすること。 |
| REQ-F-002 | 望ましくない動作 | 非画像形式または破損ファイルが入力された場合、システムは処理を中断し、ユーザーに判別可能なエラーメッセージを表示すること。 |
| REQ-F-003 | イベント駆動 | ユーザーが日報生成を実行したとき、システムは入力画像を用いて「作業内容」「進捗状況」「課題・問題点」の3セクションを含む日報本文を生成すること。 |
| REQ-F-004 | 状態駆動 | 日報生成処理中の間、システムはローディング状態を表示し、ユーザーが処理中であることを認識できること。 |
| REQ-F-005 | 望ましくない動作 | API呼び出し失敗またはタイムアウトが発生した場合、システムは失敗を通知し、再試行判断に必要なエラー表示を行うこと。 |
| REQ-F-006 | イベント駆動 | 日報生成完了時、システムは生成本文を編集可能な状態で表示すること。 |
| REQ-F-007 | イベント駆動 | ユーザーがコピー操作を実行したとき、システムは現在の編集済み日報本文をクリップボードへコピーすること。 |
| REQ-F-008 | イベント駆動 | ユーザーがMarkdown出力を実行したとき、システムは現在の編集済み日報本文をMarkdown形式で出力すること。 |
| REQ-F-009 | 状態駆動 | セッションベースの一時保持期間の間、システムは生成に必要な最小限データのみ保持し、永続DBへ保存しないこと。 |
| REQ-F-010 | イベント駆動 | ユーザーが削除操作を実行したとき、またはセッション終了時、システムは一時保存した画像および生成データを削除すること。 |
| REQ-F-011 | オプション | OCR機能が将来追加されない限り、システムはマルチモーダルモデルによる画像理解を標準フローとして扱うこと。 |

## 5. 受け入れ基準（テスト可能条件）

| AC ID | 対象要件 | 検証条件 |
|---|---|---|
| AC-001 | REQ-F-001 | 画像（PNG/JPEG）をドラッグ&ドロップ、貼り付け、ファイル選択で入力したとき、いずれの操作でもアップロード受付状態になる。 |
| AC-002 | REQ-F-002 | 非画像ファイル（例: `.txt`）入力時、生成処理へ進まずエラーメッセージが表示される。 |
| AC-003 | REQ-F-003 | 画像から日報生成後、出力に「作業内容」「進捗状況」「課題・問題点」の3見出しが含まれる。 |
| AC-004 | REQ-F-004 | 生成開始から完了/失敗までローディング表示が継続し、完了/失敗時に解除される。 |
| AC-005 | REQ-F-005 | API失敗時、ユーザーが失敗を判別できるメッセージが表示される。 |
| AC-006 | REQ-F-006 | 生成結果表示後、テキストを編集して保存なしで画面上に反映できる。 |
| AC-007 | REQ-F-007 | 編集後にコピー操作すると、クリップボード内容が画面表示テキストと一致する。 |
| AC-008 | REQ-F-008 | Markdown出力を実行すると、編集後本文がMarkdownとして出力される。 |
| AC-009 | REQ-F-009, REQ-F-010 | セッション終了または削除操作後、一時データへ再アクセスできない。 |
| AC-010 | REQ-F-011 | MVP運用時、OCR専用画面・OCR専用API呼び出しが存在しない。 |

## 6. 非機能要件

| ID | 要件 |
|---|---|
| REQ-NF-001 | 対応ブラウザはモダンブラウザとし、IE11は対象外とする。 |
| REQ-NF-002 | MVP期間（2週間想定）で実装可能な範囲に限定し、非対象機能は実装しない。 |
| REQ-NF-003 | ユーザーは処理中/失敗/完了の状態をUI上で判別できること。 |
| REQ-NF-004 | 画像および生成結果の保持はセッションベースの一時保存に限定すること。 |

## 7. セキュリティ前提・制約

| ID | 前提・制約 |
|---|---|
| REQ-SEC-001 | APIキー等の機密情報は環境変数で管理し、クライアントコードへ埋め込まない。 |
| REQ-SEC-002 | 一時保存データは最小化し、不要時に削除する。 |
| REQ-SEC-003 | 通信はHTTPS前提とし、平文通信を前提としない。 |
| REQ-SEC-004 | 永続DBはMVPで使用しないため、長期保管を前提とした個人データ保持を行わない。 |

## 8. 対象外の再確認
- モバイル最適化（レスポンシブ調整を含む本格対応）はMVP対象外。
- OCR専用フローはMVP対象外（バックアップ案としてのみ記録）。
- 永続DB（RDB/NoSQL等）を用いたデータ永続化はMVP対象外。
